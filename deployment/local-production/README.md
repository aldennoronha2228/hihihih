# Local production preparation

This is a self-hosted production **reference configuration**, not a cloud deployment or a verified production release. Docker and Caddy were unavailable in the authoring environment; image builds, Compose startup, ACME issuance, firmware compilation inside these images, and WebSocket proxying remain unverified. No infrastructure is provisioned and no credentials are shipped.

## Security and integration contract

`backend.security.SecurityMiddleware` is a pure ASGI wrapper. It does not use application/request state, log credentials, trust forwarded identity headers, or rewrite client, Host, or Origin. The production entrypoint wraps the existing backend even if the parent has not mounted the middleware yet.

For parent integration, wrap the completed FastAPI application with `SecurityMiddleware(application)` after registering routes. Mount it in production at minimum; mounting in local mode also provides body limits, Origin checking, secure headers, and concurrency limits without requiring authentication unless a token is configured. `WIREUP_DEPLOYMENT=production` without `WIREUP_ACCESS_TOKEN` fails at middleware construction. Do not fall back to an unguarded app on configuration errors. The standalone entrypoint forces production and reads the bearer token from the configured secret file before importing the backend.

Configuration:

| Variable | Default / behavior |
| --- | --- |
| `WIREUP_DEPLOYMENT` | `production` requires bearer authentication; other modes permit local unauthenticated use if no access token is configured. |
| `WIREUP_ACCESS_TOKEN` | No default. All `/api`, `/api/*`, `/docs`, `/docs/*`, `/redoc`, `/redoc/*`, and `/openapi.json` routes require `Authorization: Bearer <token>` when set. No query-string token or cookie fallback. |
| `WIREUP_ALLOWED_ORIGINS` | Comma-separated exact HTTP(S) origins. Loopback origins remain permitted; remote origins require explicit entries. No wildcard, userinfo, or path allowed. A missing Origin is permitted for authenticated non-browser clients. This is not a CORS implementation; the reference SPA uses same-origin `/api`. |
| `WIREUP_MAX_BODY_BYTES` | 600000 bytes (600 KB decimal), configurable downward only. Every HTTP request body is checked before routing, including bodies without Content-Length and chunked bodies. Invalid/ambiguous lengths are rejected. |
| `WIREUP_BODY_TIMEOUT_SECONDS` | 30 seconds to receive the entire body. |
| `WIREUP_MAX_CONCURRENT_REQUESTS` | 4 expensive requests per middleware instance/process; immediate 429 with Retry-After, no unbounded queue. Covers chat, compiler routes, compile-suffix API routes, and every hardware command because its body may invoke compilation. Slots include body upload and the complete streamed response, and are released on failure/cancellation. It does not independently budget compilation invoked internally by chat tools. Keep the existing compiler gate. |
| `WIREUP_PUBLIC_HEALTH` | `true`: production GET/HEAD `/api/health` is intercepted with only `status: ok`, production mode, and an authentication-required boolean. It does not call existing provider health or disclose models, URLs, keys, token values, or project data. `false` authenticates health and delegates to the existing route. It is a process liveness check, not provider/compiler readiness. |

API and documentation responses, including middleware denials, use no-store. HTTP responses receive nosniff, DENY framing, and no-referrer headers. TLS/HSTS belongs to Caddy. Documentation is authenticated; Swagger does not yet have a bearer-login UX, so an authenticated documentation client is required.

The trusted downstream ASGI marker is `scope['wireup.security']`, containing only `production`, `authentication_required`, `authenticated`, `trusted_origin`, and `origin_present` booleans. Parent-owned `local_connection` guards must explicitly accept production only when this middleware-written marker has `production`, `authentication_required`, and `authenticated` all true, and either Origin is absent or `trusted_origin` is true. Keep existing loopback guards otherwise. Never derive this marker from headers or waive authentication based on loopback proxy connections.

**Until that parent integration exists, deployed chat/hardware remain loopback-restricted and return 403 even after successful bearer authentication.** These files intentionally do not weaken the existing guards or spoof localhost to bypass them.

**The public application is not multiuser-ready.** A shared deployment bearer token is not user identity or project authorization. The UI has no bearer-auth login integration. Browser WebSocket APIs cannot set an Authorization header; the proxy forwards upgrades but protected runtime WebSockets remain inaccessible to that UI. Do not put access tokens in WebSocket URLs or bake tokens into SPA assets. A parent-owned authenticated session/ticket design and project ownership isolation are required before public multiuser access. The existing project runtime token is not deployment API authentication.

## Operator steps

1. Obtain a host, configure DNS for your own domain, restrict host access, and open TCP 80/443 (UDP 443 is optional for HTTP/3). Do not expose backend port 8000. Caddy persists ACME certificates in its named volume. No domain, certificate, or account is created by this repository.
2. Generate a high-entropy bearer token locally (at least 32 random bytes encoded as hex/base64url). Store it in an owner-readable file **outside the repository/build context**. Set `WIREUP_ACCESS_TOKEN_FILE` to its absolute path. Docker Compose mounts it under `/run/secrets`; local Compose secrets are file mounts, not an encrypted secrets service. Protect the original file, Docker daemon, backups, and host. Never commit or paste it into logs.
3. Store only the required provider configuration in a protected env file outside the repository. Set `WIREUP_PROVIDER_ENV_FILE` to its absolute path. Do not copy the development `.env`. Configure provider-specific keys/model endpoints deliberately. Container environment secrets are visible to Docker administrators; for stronger isolation use a dedicated secrets manager and separate compiler service.
4. Set `WIREUP_DOMAIN` to the hostname only and `WIREUP_TLS_EMAIL` to your ACME contact address. Set `ARDUINO_CLI_SHA256` to an independently verified SHA256 for the pinned Arduino CLI 1.2.2 Linux amd64 release archive. The build fails if the digest is absent or mismatched. Review current vulnerability advisories and upgrade the reference version pins before release. Tags pin versions, not immutable image digests; resolve and pin registry digests for your release platform. This build is currently linux/amd64 only.
5. From the repository root run `docker compose -f deployment/local-production/compose.yaml config --quiet`, then `docker compose -f deployment/local-production/compose.yaml build`, then `docker compose -f deployment/local-production/compose.yaml up -d`. Keep production Dockerfile-specific ignore rules; do not package credentials, development project data, caches, or remote-simulation files into the build context.
6. Verify HTTPS, certificate renewal, minimal public health, 401 without credentials on APIs/docs, 403 for unlisted Origin, authenticated chat/hardware after parent integration, 413 for oversized/chunked uploads, 429 for concurrent streams/commands, and WebSocket authentication with a header-capable test client. Run `python -m pytest tests/test_security.py -q` for middleware unit coverage. Container integration tests are still required.
7. Back up and restore-test the `projects` and Caddy volumes. One backend worker is intentional: runtime sessions and budgets are process-local, and project storage is not a multiworker database. Do not scale replicas without shared identity, ownership, state, and admission control.

## Container and compiler boundary

The image installs pinned Python requirements from `backend/requirements.txt`, pinned Arduino CLI, and `arduino:avr@1.8.6` for Uno/Nano/Mega. Optional `INSTALL_EXTENDED_CORES=true` installs `rp2040:rp2040@4.5.2` and `esp32:esp32@3.2.0` at build time. Those cores and their network download integrity/compatibility require operator verification. Library installation is not automatic; approved libraries must be pinned and added to the image, not installed by untrusted requests. ESP32 compilation does not imply QEMU simulation support; no QEMU or remote-simulation stack is included here.

The backend runs as UID 10001 with read-only root filesystem, dropped capabilities, no-new-privileges, limited CPU/RAM/PIDs, bounded ephemeral compiler storage, and persistent project storage. Core data is baked into the image; build cache goes to `/tmp`. No host Docker socket, privileged mode, host devices, or host networking is granted. Caddy serves the built SPA and proxies `/api` without stripping the prefix, preserving bearer and Origin headers and streaming responses. No access-log directive is enabled.

**This is not a compiler sandbox.** Compiler subprocesses share the backend container/user, provider credential environment, readable application/core files, writable project data, and provider-egress network. Container hardening and source include checks do not prevent compiler exploits or all preprocessor host-file access. Treat compilation input as trusted single-operator work only. For untrusted/public compilation, move compilation to disposable workers without API/provider credentials or project-volume access, deny egress, enforce filesystem/syscall/process boundaries, and validate artifacts. That architecture is not implemented here. Provider egress remains open for LLM calls, so this reference is not an egress allowlist either.

The 600 KB HTTP limit does not bound total WebSocket traffic; Uvicorn's 256000-byte message limit complements the existing runtime checks. Concurrent-request limits are not per-client rate limits and do not replace edge connection/rate controls.
