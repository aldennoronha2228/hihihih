# Remote simulation gateway

This is a separate server-to-server ESP QEMU service. It is not a public browser API and does not change the local backend's hardware commands or routes. The parent integration must use `backend.remote_simulation.RemoteSimulationClient` and enforce project/session ownership before exposing operations to users. The gateway token grants control of every session on this deployment; separate tenants need separate authorization in the parent backend or separate deployments.

## Deployment

Build from the repository root with `docker compose -f deployment/remote-simulation/compose.yaml build`, then start with `docker compose -f deployment/remote-simulation/compose.yaml up -d`. Set `REMOTE_SIMULATION_TOKEN` in the deployment environment first, using a randomly generated secret of at least 32 printable, non-whitespace ASCII characters. For example, Python's `secrets.token_urlsafe(48)` generates an appropriate value. Store it in a secret manager or a permissions-restricted environment file; do not put it in a command argument, committed file, browser configuration, URL, or logs. Do not paste expanded `docker compose config` output into reports because it contains the token.

The compose service binds only `127.0.0.1:8080`. Install `nginx.conf` in a host nginx HTTP context, replace the example domain and certificate paths, and verify the nginx configuration before reloading. TLS is mandatory for backend connections. Restrict ingress further to authorized backend hosts through a firewall or VPN. The HTTP listener redirects to HTTPS, but the API client refuses HTTP and never follows redirects. Do not publish port 8080 on a public interface or disable certificate verification. Access logs are disabled; do not enable header/body logging or debug traces containing credentials or firmware.

Set `REMOTE_SIMULATION_URL=https://your-emulator-domain` and the same `REMOTE_SIMULATION_TOKEN` in the parent backend's environment only. A fixed deployment path prefix is supported if the reverse proxy strips that prefix. User/model supplied URLs are not permitted. The client validates HTTPS, rejects URL credentials/query/fragment, ignores proxy environment variables, and has connect/pool timeouts of 5 seconds and read/write timeouts of 30 seconds. Close it with `async with` or `await aclose()`.

The image builds native Espressif QEMU from commit `40edccac415693c5130f91c01d84176ae6008566` and retains its installed data/ROM tree and corresponding source. It uses the vendored Velxio manager from revision `3e45cada3f362ce61fe2c8515f7fee0f7acf4113`; `upstream.sha256` verifies the exact copied source and license files. The image preserves the upstream license/commercial-license/provenance files. Velxio is AGPLv3/commercial dual-licensed, and QEMU has its own license obligations. Production distribution/network deployment must comply with applicable licenses or obtain appropriate commercial rights; ownership/control of this server does not remove those obligations.

Run one Uvicorn worker only: sessions, locks, and capacity are in memory. The container is non-root and read-only, with bounded temporary storage, CPU, memory, process count, logs, and no added capabilities. Four sessions including retained terminal sessions are allowed by default. Container shutdown provides 35 seconds for cleanup. Firmware and session state do not persist across restart. This is not a substitute for VM-level isolation for hostile firmware.

## Exact integration contract

Every route, including health/capabilities, requires exactly one `Authorization: Bearer <token>` header. Missing, duplicate, or incorrect authentication returns 401 before request body validation. API docs/OpenAPI are disabled. No token is returned by routes or client error messages.

- `await client.health()` → `GET /health`: `status: "ok"`, `emulator_available` (boolean), and `upstream_revision`. Healthy HTTP does not prove firmware boots.
- `await client.capabilities()` → `GET /capabilities`: `boards` is a map of actually probed machine support, with each entry containing `machine`, `serial: true`, `gpio: false`. Other fields are `max_flash_bytes: 16777216`, `max_sessions: 4`, `session_timeout_seconds: 300`, `gpio_supported: false`, `linux_images_supported: false`, `websocket_events: false`. Do not assume all board IDs are available merely because the client accepts them.
- `await client.start(board_id, firmware_b64)` → `POST /sessions`, JSON `{board_id, firmware_b64}`, success 201. Board IDs: `esp32-devkit-v1`, `esp32-devkit-c-v4`, `esp32-s3`, `esp32-c3`. Firmware is standard base64 of a **merged raw flash image** containing 1 byte to 16 MiB, with bootloader/partition/application at their required flash offsets. ELF, UF2, and application-only binaries are not merged flash. Server startup waits up to 20 seconds for an actual UART connection and a live QEMU process; this does not prove application correctness. No user-selected QEMU arguments, networking, paths, Linux images, GPIO input, or shell commands are accepted.
- `await client.read(session_id, after=0)` → `GET /sessions/{session_id}?after=0`. `results(...)` is a backward-compatible alias. Session IDs are server-issued lowercase 32-character hexadecimal strings; cursor is a nonnegative integer (not boolean).
- Start/read/stop return `{session_id, board_id, status, cursor, events, truncated, serial, gpio}`. Status is `starting`, `running`, `stopped`, `expired`, `failed`, or `exited`. Events have `{sequence, type, data}` and monotonically increasing sequence numbers. Poll with the previous `cursor`; returned events have sequence greater than `after`. At most 512 events are retained, serial chunks are capped at 4096 characters, and `truncated` indicates missed evicted events. `serial` concatenates serial data from only this response; `gpio` collects GPIO events but is normally empty because native Espressif GPIO is not supported. Recognized event types are `system`, `serial_output`, `gpio_change`, `error`; emulator errors are sanitized. No fabricated pin state is returned.
- `await client.serial_input(session_id, data)` → `POST /sessions/{session_id}/input`, JSON `{type: "serial", data_b64}`. `data` must be 1–4096 bytes. Success returns `{session_id, accepted_bytes}`; it acknowledges transport acceptance, not application processing.
- `await client.stop(session_id)` → `POST /sessions/{session_id}/stop`, JSON `{}`. Repeated stop is safe while retained. Stops cancel and await boot/background tasks, close UART writers, terminate/kill and reap QEMU, and remove temporary flash files. Client `aclose()` closes HTTP only; it does not stop remote sessions. Parent callers must stop owned sessions in `finally`, including cancellation/failure paths.

Limits are configurable through `create_app` for embedders/tests: `max_sessions` 1–16, absolute `session_timeout` 1–3600 seconds, `startup_timeout` >0–25 seconds, `retention` 1–300 seconds. Production factory defaults apply to compose. The startup budget is capped by the absolute session TTL even if `startup_timeout` is larger. The once-per-second sweeper expires active sessions by age from creation, not activity; polling does not extend TTL. It cleans failed/exited processes and deletes retained records at creation + TTL + retention (default 360 seconds). Cleanup is serialized per session. A start request that fails or is cancelled cleans and removes its session immediately. HTTP request disconnection does not reliably cancel an ASGI handler, so parent cleanup and maximum TTL are still required. Lifespan shutdown stops all sessions; no keepalive task or process is intentionally detached.

Errors: 401 unauthorized; 404 unknown/removed session; 409 input to a non-running session; 413 request body exceeds the bounded base64 envelope; 422 invalid/extra payload or unavailable board; 429 capacity including retained records; 502 startup/input failure; 504 startup/input timeout. The client reports safe HTTP-status errors without echoing response bodies or remote exceptions. No automatic retries are made for start, since a failed transport response may leave a session until TTL.

## Validation and smoke checks

From the repository root, run `python -m pytest deployment/remote-simulation/test_remote_simulation.py -q` and `python -m compileall -q backend/remote_simulation.py deployment/remote-simulation`. Tests use mocked HTTP transports/managers/processes and do not boot QEMU.

With backend environment variables configured, run `python deployment/remote-simulation/smoke.py` for authenticated health/capability checks. To test actual start/read/stop, use `python deployment/remote-simulation/smoke.py --board esp32-c3 --firmware /path/to/merged-flash.bin --seconds 5`. Add `--expect-serial READY` to require a known application marker (maximum check duration 60 seconds). The smoke check never prints the token or UART contents and stops any successfully created session in `finally`. It does not test serial input because arbitrary input can alter firmware behavior.

The package was validated locally with mocked contracts and Python compilation only. Docker image build, native QEMU binary/dependency probes inside that image, TLS/nginx deployment, and real firmware boot must be verified on the deployment host before claiming production readiness. No actual Docker/QEMU verification was available in the completion environment.
