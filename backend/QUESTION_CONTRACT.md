# Agent question and resume contract

`stream_agent(model, history, project_id=None, runtime_token=None, requirements=None, *, max_tool_calls=None, max_model_calls=None, timeout_seconds=None)` remains backwards compatible. Parent should validate `ChatRequest.project_answers` as a nonempty object mapping question IDs to selected option IDs or confirmed text (maximum 20 entries; IDs 80 characters, values 1000 characters), then pass it as `requirements=payload.project_answers`. Do not accept a model-produced confirmation flag. Requirements are request context, not persistent agent state; send the confirmed object on subsequent build requests for that project.

Alternative resume when the parent has not wired the field: the latest user message starts with `Project requirements confirmed:` followed by a JSON object on the same line, then a newline and `Build now using tools`. The agent validates this object itself. Do not use this prefix for unconfirmed guesses.

A project-scoped initial build/create/wire/compile request without requirements binds only `ask_project_questions` with required tool choice. This planning tool returns `{questions:[{id,question,options:[{id,label,description?}]}],summary}`. There are 3–5 questions, each with 2–6 options; text lengths and IDs are bounded and IDs unique. The model should ask useful unresolved circuit decisions (behavior, components, timing, power/runtime constraints), not demand a different board when the project already has one. The agent emits normal tool start/end, then `{type:"questions",questions:[...],summary:"..."}`, and ends immediately with `{type:"done",status:"awaiting_answers",reason:"requirements_required",...}`. No mutation runs, and no extra model call or final answer occurs after valid questions. The frontend renders choices and sends actual selections on resume.

All project mutation/compile/run tools are blocked until requirements are confirmed, even if the model ignores instructions. Read/catalog/calculator tools are not mutations. Confirmed explicit build requests must execute successful mutation/runtime tools; advice-only turns end with error reason `build_not_executed`, not fabricated completion. Compile requests must attempt compile; missing results and failed work are reported as incomplete. Tool feedback and final done metadata contain `changes` counts based only on successful operations plus `successfulTools`. A final narration summarizes actual changed objects and compilation/runtime status; compilation is not simulation execution.

Defaults: 60 tool calls, 48 model calls, 300 seconds, bounded graph recursion. Optional caller overrides are capped at 100 tools, 80 model calls, and 300 seconds. Cancellation propagates; no graph checkpoints, hidden retry, or mutation replay.

The hardware domain still has its original 16 tools. `ask_project_questions` is agent-local, making 17 total bound tools on normal/resumed turns; it never dispatches to hardware.command. Parent owns app/frontend integration. Agent worker owns only agent.py, tests/test_agent.py, and this explicitly requested contract.
